# 示例项目 用例图 (Use Case Diagram)

## 1. 普通用户用例

```mermaid
usecaseDiagram
    actor "普通用户" as User
    actor "游客" as Guest

    package "用户系统" {
        usecase "注册账号" as UC1
        usecase "登录系统" as UC2
        usecase "浏览商品" as UC3
        usecase "搜索商品" as UC4
        usecase "加入购物车" as UC5
        usecase "提交订单" as UC6
        usecase "在线支付" as UC7
        usecase "查看订单" as UC8
        usecase "评价商品" as UC9
    }

    User --> UC2
    User --> UC3
    User --> UC4
    User --> UC5
    User --> UC6
    User --> UC7
    User --> UC8
    User --> UC9

    Guest --> UC1
    Guest --> UC3
    Guest --> UC4

    UC6 ..> UC5 : include
    UC6 ..> UC7 : include
    UC9 ..> UC8 : include
```

### 图表解释

#### 1. 整体概述
- 这张图讲的是：普通用户和游客在系统中的功能权限
- 解决什么问题：明确不同角色的功能边界
- 核心看点：include 关系展示功能依赖

#### 2. 关键元素说明
- **普通用户**：已注册并登录的用户，拥有完整功能权限
- **游客**：未登录用户，仅可浏览和搜索
- **用例**：系统提供的具体功能点

#### 3. 关键流程说明
- **注册流程**：游客通过注册账号成为普通用户
- **购物流程**：浏览/搜索 → 加入购物车 → 提交订单 → 支付
- **依赖关系**：提交订单必须包含购物车和支付

#### 4. 关键技术解释
- **RBAC（基于角色的访问控制）**：通过角色分配权限
- **Session 管理**：登录状态维护机制
- **权限校验**：每个功能点前的身份验证

#### 5. 设计意图
- 为什么要这样设计：区分用户等级，提供个性化服务
- 解决了什么痛点：游客快速体验，注册用户享受完整功能
- 带来了什么好处：降低使用门槛，促进用户转化
- 如果不这样会怎样：强制注册导致用户流失

## 2. 管理员用例

```mermaid
usecaseDiagram
    actor "管理员" as Admin
    actor "系统" as System

    package "管理系统" {
        usecase "商品管理" as UC10
        usecase "订单管理" as UC11
        usecase "用户管理" as UC12
        usecase "数据统计" as UC13
        usecase "系统配置" as UC14
        usecase "日志审计" as UC15
    }

    Admin --> UC10
    Admin --> UC11
    Admin --> UC12
    Admin --> UC13
    Admin --> UC14
    Admin --> UC15

    UC10 ..> UC13 : extend
    UC11 ..> UC13 : extend
    System --> UC15
```

### 图表解释

#### 1. 整体概述
- 这张图讲的是：管理员在后台系统的管理功能
- 解决什么问题：展示管理员的系统运维能力
- 核心看点：extend 关系展示可选功能

#### 2. 关键元素说明
- **管理员**：系统运维人员，拥有最高权限
- **系统**：自动执行的定时任务和监控
- **extend**：可选扩展功能

#### 3. 关键流程说明
- **商品管理**：增删改查商品信息
- **数据统计**：基于商品和订单数据生成报表
- **日志审计**：系统自动记录操作日志

#### 4. 关键技术解释
- **后台管理系统**：通常采用独立部署的管理端
- **操作日志**：AOP 切面编程记录所有管理操作
- **数据权限**：不同管理员可能只能看到部分数据

#### 5. 设计意图
- 为什么要这样设计：业务运营需要独立的管理入口
- 解决了什么痛点：业务人员无需技术背景即可管理系统
- 带来了什么好处：提高运营效率，降低维护成本
- 如果不这样会怎样：所有操作需要开发人员介入，效率低下
